# SUBIL OS — Architecture Baseline

## 1. الرؤية
SUBIL OS هو نظام تشغيل متكامل للنشاط، وليس إضافة WordPress فقط. يجب أن يدعم المتجر والحسابات والعملاء والفنيين والخدمة الميدانية والمالية والمخزون والتسويق والتكاملات والذكاء الاصطناعي من منصة واحدة.

## 2. المبادئ
1. API-first مع فصل الواجهات عن منطق الأعمال.
2. Modular architecture تسمح بتطوير كل وحدة مستقلة.
3. RBAC وصلاحيات دقيقة لكل مستخدم.
4. Audit log للعمليات الحساسة.
5. Multi-city / multi-branch من البداية.
6. قابلية Multi-tenant مستقبلًا دون فرض تعقيد SaaS على الإصدار الأول.
7. التكاملات الخارجية عبر adapters حتى يمكن تغيير مزود SMS/WhatsApp/Payment دون إعادة بناء النظام.
8. AI لا ينفذ عمليات حساسة دون صلاحيات وقواعد موافقة واضحة.

## 3. المستخدمون
- العميل
- الفني
- المشرف الميداني
- خدمة العملاء
- المبيعات والتسويق
- المخزون والمشتريات
- المالية
- مدير الفرع/المدينة
- الإدارة العليا
- Super Admin

## 4. دورة الطلب والخدمة
الدفع/إنشاء الطلب → تحديد نوع التنفيذ (شحن فقط/تركيب/خدمة) → إسناد حسب المدينة → جدولة داخلية حسب جدول الفني → إشعار العميل → الفني يرى المهمة دون كشف رقم الجوال → في الطريق → تم الوصول → بدء العمل → إثبات بالصور/الفيديو → إغلاق → تقييم العميل → احتساب المستحق المالي → إنشاء تذكير الصيانة اللاحق.

لا يطلب من العميل اختيار موعد تركيب أثناء الشراء. الجدولة تشغيلية من لوحة الإدارة، وإعادة الجدولة تتم عبر خدمة العملاء/النظام.

## 5. مستحقات الفني
يخزن النظام تكلفة المنتج قبل الضريبة ويحسب هامش الربح قبل الضريبة. يمكن أن يكون أجر الفني مبلغًا ثابتًا لكل طلب أو نسبة. نموذج النسبة الافتراضي يبدأ 30% من هامش الربح، مع إمكانية رفعه 5 نقاط بعد تحقق قاعدة أداء معتمدة لفترتين شهريتين، وبحد أقصى 50%. قواعد الترقية تحفظ كسياسة قابلة للتعديل ولا تكتب كأرقام ثابتة في منطق النظام.

## 6. Identity
الدخول الأساسي برقم الجوال + OTP، مع دعم قنوات بديلة ومزودين مختلفين. يحتفظ النظام بموافقة العميل على قنوات التواصل والتذكيرات وفق نوع الرسالة.

## 7. CRM
ملف موحد للعميل: الطلبات، الأجهزة، مواقع الخدمة، الضمان، التركيبات، الصيانة، التقييمات، المحادثات، الحملات والموافقات.

## 8. Marketing & Social Hub
ربط القنوات المتاحة رسميًا عبر APIs: إدارة المحتوى، التقويم، النشر، الرسائل والتعليقات حيث تسمح المنصة، Attribution، الحملات، SEO، استعادة السلات، وإعادة الاستهداف. قدرات كل شبكة تبقى مقيدة بما تسمح به واجهاتها وسياساتها.

## 9. AI Agents
وكلاء منفصلون للتسويق، المبيعات، خدمة العملاء، العمليات، المالية، المخزون، والتحليل التنفيذي. جميع إجراءات الوكلاء تسجل في audit log، مع Human approval للإجراءات المالية/النشرية/الحساسة التي تحددها السياسة.

## 10. التطبيقات
- Customer Web/PWA
- Admin Web
- Technician PWA/Mobile
- Customer Mobile
- Backend/API
- Worker/Queue services

بوابة الفني تستخدم مخزن IndexedDB خاصًا بالنطاق لحفظ الإسقاط التشغيلي الآمن فقط، دون رقم جوال العميل. انتقالات الحالة غير المتصلة تحفظ كأوامر مرتبة وتُعاد عند عودة الشبكة؛ التعارضات النهائية لا تعاد بلا نهاية، وإغلاق المهمة المالي لا يتم دون اتصال لأنه يتطلب رفع الإثبات ومعاملة خادمية واحدة.

## 11. نطاق MVP
Identity + Commerce integration + CRM + Field Service + Technician workflow + Notifications abstraction + Finance technician settlement + Admin dashboard + audit/event foundation.

## 12. ما بعد MVP
Inventory/Procurement المتقدم، Social Hub، Marketing automation، AI Agents، تطبيقات native، التحليلات المتقدمة، وMulti-tenant التجاري.
